We're building the live ingestion pipeline for an SDR (Sceptre) that streams IQ data over UDP
using a VITA-49.2 subset. Two reference files are in the repo:
  - Sceptre_VITA-49_Streaming_Format.pdf — the authoritative wire format (VRL disabled, no VRT
    trailer, 20-byte big-endian header). Read it for exact bit offsets and the cited §7.1.5.x
    context-field formats; do NOT trust offsets from memory.
  - recieve_udp.py — an existing capture tool. It binds a UDP socket and pickles received
    packets to disk as {"start_time_ns", "duration_seconds", "packets": [(ts_ns, src_ip,
    src_port, payload_bytes), ...]}. We are KEEPING this format and reusing these captures for
    offline testing (see Stage 1).
  - Also a light project skeleton has been set up so far with empty files that will need to be filled as we go such as README.md, pyproject.toml, .gitignore, etc. Make sure you look at the current existing architecture.

GOAL: UDP packets → interpret → accumulate → emit (numpy array + typed context dict) to
downstream consumers (FFT / recording / audio).

DELIVERABLE: a staged implementation plan as a markdown file in /docs. Each stage must be a
self-contained prompt I can hand to a CLI coding agent, containing: (1) objective, (2) files to
create/modify, (3) the exact implementation prompt, (4) acceptance criteria. Stages must be
independently testable and build on each other. Use only stdlib + numpy.

────────────────────────────────────────────────────────────────────────
THREAD LAYOUT (the whole runtime in one picture)
────────────────────────────────────────────────────────────────────────
  Thread A — SOURCE: socket OR pickle-file → pushes raw packet bytes onto a bounded raw_queue.
             Dumb and fast. Never parses.
  Thread B — INTERPRETER + BUFFER: pulls raw bytes, parses header, decodes context, owns
             current_context, accumulates data payloads, flushes. Emits {array, context} units
             to downstream consumers via a callback (or a second queue).

The buffer lives in Thread B alongside the interpreter — it is not its own thread.

────────────────────────────────────────────────────────────────────────
STAGE 1 — SOURCE ABSTRACTION (live UDP + pickle replay, shared interface) + keep recorder
────────────────────────────────────────────────────────────────────────
Define ONE source interface whose only job is "emit raw packet bytes onto raw_queue." Two
implementations satisfy it:
  - LiveSource: UDP socket loop in its own thread. One datagram = one VITA-49 packet (UDP
    framing + no VRL guarantees this). Push the raw payload bytes; do NOT parse.
  - ReplaySource: reads an existing udp_capture_*.pkl, iterates packets, pushes packet[3]
    (payload_bytes) onto the same raw_queue. Optionally pace by the recorded ts_ns to mimic
    real timing; un-paced (fire as fast as possible) is fine for v1 tests.

This refactor is the point: the interpreter and buffer can be developed and tested entirely
offline against existing captures with no SDR attached.

raw_queue must be a BOUNDED thread-safe queue with an explicit overflow policy:
drop-oldest-and-count. A real-time SDR feed must shed samples and log the drop count if the
consumer stalls — never grow unbounded, never block the socket.

Keep recieve_udp.py's capture-to-disk capability as a "recorder." Where practical, factor the
socket-read code so LiveSource and the recorder share it, but at minimum the .pkl format must
stay byte-compatible so existing and future captures replay correctly.

Modify recieve_udp.py so pickle captures are written into a `recordings/` directory at the
project root (created if missing), e.g. recordings/udp_capture_<timestamp>.pkl, instead of the
current working directory. The existing default_output_filename() should resolve to that folder.

Recording must be available concurrently with live operation: a single socket read fans out to
two INDEPENDENT sinks — raw_queue (the live path, lossy: drop-oldest when full) and, when
recording is enabled, the capture. The sinks are decoupled: a raw_queue overflow drop must NOT
remove anything from the capture, so saved recordings stay complete even when the live consumer
stalls. Recording stays bounded (by duration as it is today, or a max-packet/byte cap) — it must
not accumulate an unbounded in-memory list during an indefinite live session. The capture append
must be cheap and in-memory; it must never block the socket read.

────────────────────────────────────────────────────────────────────────
STAGE 2 — INTERPRETER (header parse + context decode + data trim; owns current_context)
────────────────────────────────────────────────────────────────────────
Pulls raw bytes from raw_queue. Parses the 20-byte VRT header:
  - packet_type = first 4 bits: 0001 = IF data packet, 0100 = IF context packet
  - packet counter = mod-16, INDEPENDENT per stream (data vs context)
  - packet_size = number of 32-bit words (incl. header)
  - stream_id, integer timestamp (Unix s), fractional timestamp (picoseconds)
  - time = integer_s + fractional_ps / 1e12

Holds CURRENT_CONTEXT as interpreter state — data packets are undecodable without it.

CONTEXT packet → decode payload into a TYPED dict (numbers, not a string). Parse the Context
Indicator Field bit flags, then decode each present field. Fixed-point conversions (VERIFY
against the PDF's cited sections, do not trust these blindly):
  - RF freq / sample rate / bandwidth: int64 with radix point after bit 20 → value_Hz =
    raw_int64 / 2**20
  - gain: two 16-bit subfields (stage1 bits 0–15, stage2 bits 16–31), each dB = raw_int16/128,
    summed
  - IF Data Packet Payload Format (§7.1.5.18): decode → real-vs-complex + item size in bits →
    bytes_per_sample. ALSO assert it equals the expected complex float32 (8 bytes) and fail
    loudly if Sceptre's config differs.

DATA packet → num_samples = floor((packet_size*4 - 20) / bytes_per_sample). Take EXACTLY
num_samples * bytes_per_sample bytes — trim the 32-bit-word padding. Do NOT materialize numpy
here; pass trimmed bytes + dtype downstream.

Use the per-stream packet counter to DETECT dropped packets. On a mod-16 gap, flag it on the
emitted data record (e.g. metadata["gap_before"] = True) and log it — the buffer uses this flag
(see Stage 3 gotcha #4).

Emit per-packet records (messages, not storage):
  {type, metadata{stream_id, counter, timestamp, packet_size, dtype, bytes_per_sample,
   is_complex, gap_before}, context (typed dict | None), data (trimmed bytes | None)}

Startup edge case: a data packet arriving before the first context packet is undecodable —
drop-with-warning until the first context arrives (≤1s, since context is periodic).

────────────────────────────────────────────────────────────────────────
STAGE 3 — INGEST BUFFER (routing model, accumulation, four flush triggers, single conversion)
────────────────────────────────────────────────────────────────────────
The buffer does NOT store per-packet dicts. The per-packet record is a message: push(record)
inspects record["type"], pulls out the ONE thing it needs, and discards the rest. N data
packets collapse into one growing list of byte-chunks + a sample count; context collapses into
one dict that gets overwritten.

State held between flushes:
  - _chunks: list[bytes]   (one trimmed payload appended per data packet)
  - _num_samples: int
  - _dtype, _bytes_per_sample, _is_complex   (latched from the first chunk of a window)
  - _start_timestamp        (packet timestamp of the first chunk in the window)
  - _first_arrival          (monotonic clock, for the age trigger)
  - _current_context: dict | None   (separate from accumulation)

push(record) routing:
  - type == "context": compare to current; maybe flush; then replace _current_context.
    Appended to nothing.
  - type == "data": if first chunk of window, latch dtype/timestamp/arrival; append
    record["data"]; bump _num_samples; check size + gap triggers.

FOUR flush triggers:
  (a) size  — _num_samples >= max_samples
  (b) context changed — a REAL diff (see gotcha #1 and #2)
  (c) age   — polled, not reactive (see gotcha #3)
  (d) counter gap — contiguity break (see gotcha #4)

flush(): if _chunks is empty, return. Otherwise join ONCE and convert ONCE — this single
conversion is only correct because a data-format change is a hard flush (gotcha #1), so every
chunk in the window shares one dtype:
  raw = b"".join(self._chunks)
  arr = np.frombuffer(raw, dtype=self._dtype).astype(np.float32)   # native-endian FIRST
  if self._is_complex: arr = arr.view(np.complex64)                 # each [I,Q] pair → 1 sample
  emit {samples: arr, context: self._current_context, start_timestamp, num_samples}
Then reset _chunks/_num_samples/_start_timestamp/_first_arrival — but KEEP _current_context.

────────────────────────────────────────────────────────────────────────
CRITICAL CORRECTNESS — four things the CLI agent WILL get wrong unless the plan spells them out.
Every one of these must appear in the relevant stage prompt AND its acceptance criteria.
────────────────────────────────────────────────────────────────────────
1) CONTEXT-CHANGE ORDERING. In the context handler, flush() must run BEFORE adopting the new
   context. This is not incidental: the samples being flushed were captured under the OLD
   frequency/rate, so the emitted array must be labeled with the OLD context. Adopt the new
   context only after the buffer is empty. Order: flush+emit (old context) → set
   _current_context = new → subsequent data accumulates under new context.

2) PERIODIC CONTEXT IS NOT A CHANGE. Sceptre sends a context packet every second WHETHER OR NOT
   anything changed, AND immediately on a real change. The context handler is therefore hit
   constantly. Only flush on a real diff: compare a configurable set of flush_fields (default:
   RF frequency, sample rate, data format) and IGNORE counter/timestamp, which always differ.
   An identical heartbeat must NOT trigger a flush — otherwise you flush ~60×/min for nothing.
   A data-format change is a hard flush (you cannot frombuffer a mixed-dtype buffer); freq/rate
   changes flush because they change the samples' meaning.

3) AGE TRIGGER CANNOT BE REACTIVE. If the stream stalls, no packet arrives, push() never runs,
   and a purely reactive buffer sits on samples forever. The interpreter loop must POLL between
   dequeues, e.g. a maybe_flush_on_age() that flushes when _chunks is non-empty and
   monotonic() - _first_arrival >= max_age_s. Wire this into the dequeue loop (e.g. via a
   queue.get timeout), not only into push().

4) DROPPED PACKETS BREAK CONTIGUITY. The emitted unit carries ONE start_timestamp and consumers
   reconstruct each sample's time as start + n/sample_rate — valid ONLY if samples are gapless.
   A mod-16 counter gap mid-window means the samples are NOT contiguous in time. Cheapest
   correct policy: treat a counter gap as a flush boundary (trigger d) so every emitted array is
   genuinely continuous — i.e. in _handle_data, if metadata["gap_before"] is set, flush the
   current window BEFORE appending the new packet. v1 may instead just log the gap, but the plan
   must call this out explicitly as a known correctness limitation.

────────────────────────────────────────────────────────────────────────
IMPLEMENTATION NOTES
────────────────────────────────────────────────────────────────────────
- Accumulator type: list[bytes] + b"".join() is preferred — it maps cleanly to "one packet =
  one chunk appended" and makes the single-conversion story obvious. A bytearray you .extend()
  is equally valid and gives a running length for free. Do NOT use `bytes += chunk` in a loop
  (quadratic reallocation).
- Timestamps: the packet's embedded timestamp is authoritative (SDR sample time). Keep arrival
  time only for latency/age diagnostics.
- Tests: every stage ships unit tests that run against the existing udp_capture_*.pkl captures
  via ReplaySource — no SDR required. Include at minimum: a header-parse test on known bytes, a
  context-decode test asserting the fixed-point conversions, a "periodic identical context does
  not flush" test, a "freq change flushes with OLD context label" test, and a padding-trim test
  on a sub-32-bit format.
